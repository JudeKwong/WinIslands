# 插件安全模型

WinIslands 的插件是**本地代码**，以当前用户权限运行。下面说明 3.1.8 起提供的防护边界，以及这些边界的局限，帮助你判断能否信任一个插件。

## 1. 进程隔离

插件不会被加载进 WinIslands 主进程，而是由主程序启动独立子进程，读取其标准输出中的 JSON。因此：

- 插件崩溃、死循环或输出格式错误**不会**导致灵动岛崩溃；
- 每次运行都有超时上限（`plugin.json` 的 `timeout_seconds`，默认 10 秒），超时即终止；
- 主程序退出时，所有插件进程会被一并结束。

## 2. Job Object 资源限制

每个插件进程都放入独立的 Windows Job Object：

| 限制 | 值 |
| --- | --- |
| 单进程内存 | 1 GB |
| 整个 Job 内存 | 1 GB |
| 子进程创建 | 未声明 `processes` 权限时禁止 |
| 主程序退出 | 自动结束全部插件进程（KillOnJobClose） |

超过内存上限会被系统直接终止，不会拖慢整机。

## 3. 权限声明

`plugin.json` 的 `permissions` 必须是白名单内的值：

| 权限 | 含义 | 是否强制 |
| --- | --- | --- |
| `network` | 插件需要联网 | 声明式，用于提示与审计 |
| `filesystem` | 插件需要读写本地文件 | 声明式，用于提示与审计 |
| `processes` | 插件需要创建子进程 | **强制**：未声明时 Job Object 禁止创建子进程 |

未知权限名会被拒绝，避免插件用自定义权限名伪装成「已声明」。导入或首次运行时，插件管理器会展示名称、ID、版本与申请权限，需要你确认后才运行。

> 网络与文件系统目前是**声明式权限**，不构成操作系统级沙箱。声明了 `filesystem` 的插件仍可读写当前用户能访问的任意文件。这是为了保持插件能力（读取系统状态、调用本机工具）而做的取舍。

## 4. 入口哈希校验

- 导入压缩包时，若 `plugin.json` 声明了 `sha256`，必须与入口文件实际哈希一致，否则**拒绝导入**；
- 本地插件在清单缺少 `sha256` 或与其不一致时**不会运行**，需要在插件管理器点击「校验并信任」；
- 信任后把真实哈希写回清单，此后入口文件被修改会再次要求确认。

这可以防止「确认时是一个插件、运行前被替换成另一个」的篡改。

## 5. 环境变量清理

插件进程只继承必要环境变量，避免把父进程中的令牌、代理凭据等敏感信息泄露给插件。

## 6. 输出校验

插件标准输出必须是单个 JSON 对象；解析失败会当作一次失败处理并记录日志，不会把任意文本渲染到岛上。裁剪后的 JSON 超过大小上限会被拒绝。

## 7. 你仍然需要做的事

- **只安装来源可信的插件**。声明式权限不等于沙箱，插件仍拥有当前用户的文件访问能力。
- **升级后重新确认**。哈希变化说明插件内容变了，确认前先看差异。
- **不要用管理员权限运行**不认识的插件。
- **看输出**。插件页会展示最近一次运行的错误，异常频繁的插件应停用。

## 8. 报告安全问题

如果在插件机制本身（隔离、权限校验、哈希校验）发现可绕过的问题，请通过 <https://github.com/JudeKwong/WinIslands/issues> 私密反馈，不要公开细节。
